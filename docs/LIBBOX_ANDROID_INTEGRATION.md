# Android libbox integration contract

Pinned runtime: `com.github.singbox-android:libbox:1.14.3`.

This document records the API contract verified against the matching upstream
sing-box tag (`v1.14.3`). Do not implement against the moving `testing` branch
or copy an unrelated client's application layer.

## Runtime sequence

1. Initialize libbox once with application-owned base, working, and temp paths.
2. Start one `CommandServer` for the VPN service process.
3. Supply a service-owned implementation of libbox `PlatformInterface`.
4. Start a validated sing-box JSON profile with `StartOrReloadService`.
5. When libbox calls `OpenTun(TunOptions)`, configure Android's
   `VpnService.Builder` from the supplied options and call `establish()`.
6. Return the established descriptor to libbox and retain the owning
   `ParcelFileDescriptor` for deterministic shutdown.
7. On stop/revoke/error: close the service profile, close the command server,
   then close the retained descriptor exactly once.

The UI must not report CONNECTED merely because the foreground service or
command server started. It may report CONNECTED only after the profile start
succeeds and the service lifecycle confirms the tunnel is active.

## Verified libbox 1.14.3 API

The generated `io.nekohasekai.libbox.PlatformInterface` corresponds to the
Go interface in `experimental/libbox/platform.go`. Its core TUN method is:

```go
OpenTun(options TunOptions) (int32, error)
```

The same interface also includes network/interface monitoring, connection
owner lookup, local DNS transport, notification, neighbor monitoring, shell,
user lookup, and bridge callbacks. Kotlin signatures are generated by gomobile;
inspect the pinned artifact's source/API before implementing every override.

Command server lifecycle:

```kotlin
val server = CommandServer(handler, platformInterface)
server.start()
server.startOrReloadService(configJson, overrideOptions)
server.closeService()
server.close()
```

The handler contract includes service stop/reload, system proxy status,
system proxy enablement, native crash trigger, debug logging, and SSH-agent
connection. Implement unsupported optional features explicitly and safely;
do not pretend they work.

## TUN descriptor ownership rules

- Do not create a TUN before a validated profile requests one.
- Do not return a descriptor from a closed `ParcelFileDescriptor`.
- Keep the `ParcelFileDescriptor` alive while libbox owns the tunnel.
- Make cleanup idempotent; stop, revoke, reload failure, and service destroy
  can converge on the same cleanup path.
- Do not close the descriptor before the libbox service has stopped using it.
- Never mark the tunnel connected on a permission grant or foreground-service
  start alone.

## First integration scope

The first real profile milestone should support only the basic full-tunnel
case: IPv4/IPv6 addresses, DNS servers, MTU, automatic routes, and package
include/exclude lists. Unsupported options must fail with a clear error rather
than silently producing a partially configured tunnel.

Before enabling traffic, add tests for profile parse failure, TUN establish
failure, repeated start/stop, permission revocation, descriptor cleanup, and
service destruction. Device validation must then cover DNS, IPv4, IPv6,
reconnect, and stop behavior.
